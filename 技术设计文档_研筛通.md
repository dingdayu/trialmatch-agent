## 1. 技术选型总览

### 1.1 整体架构

采用 **前后端分离** 架构，AI 任务异步处理。

```
┌─────────────────────────────────────────────────────────────┐
│                        前端 (SPA)                           │
│              React 18 + TypeScript + Ant Design             │
└──────────────────────┬──────────────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────────────────┐
│                  后端应用服务 (FastAPI)                       │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌───────────────┐  │
│  │ 用户认证  │ │ 项目管理  │ │ 受试者管理│ │ 文件管理      │  │
│  └──────────┘ └──────────┘ └──────────┘ └───────────────┘  │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌───────────────┐  │
│  │ 入排标准  │ │ AI 调度   │ │ 结果查询  │ │ 审计日志      │  │
│  └──────────┘ └──────────┘ └──────────┘ └───────────────┘  │
└──────┬──────────────┬───────────────────┬───────────────────┘
       │              │                   │
┌──────▼──────┐  ┌─────────▼────┐┌─────────▼────┐
│  PostgreSQL  │ │  本地文件系统 │ │  redis        │
│  业务数据库   │ │              │ │              │
└─────────────┘  └─────┬──────┘  └───────────────┘
                      │
              ┌───────▼────────┐
              │  AI Worker 集群  │
              │  (Celery + LLM) │
              └────────────────┘
```

### 1.2 技术栈明细

| 层级         | 技术选型                        | 版本要求    | 选型理由                                                     |
| ------------ | ------------------------------- | ----------- | ------------------------------------------------------------ |
| **前端**     | React + TypeScript              | 18.x / 5.x  | 生态成熟，组件化开发效率高                                     |
| **UI 框架**  | Ant Design                      | 5.x         | 企业级 SaaS 组件库，表格/表单/布局组件丰富                     |
| **状态管理** | Zustand                         | 4.x         | 轻量、简洁，适合中型应用                                       |
| **HTTP 客户端** | Axios                        | 1.x         | 拦截器、取消请求支持完善                                       |
| **后端框架** | FastAPI                         | 0.110+      | 高性能异步框架，自动生成 OpenAPI 文档，类型安全                |
| **ORM**      | SQLAlchemy                      | 2.x         | 成熟稳定的 Python ORM，支持异步                                |

| **任务队列** | Celery                          | 5.x         | 分布式异步任务处理，支持任务重试和监控                         |
| **对象存储** | MinIO                           | 最新版      | S3 兼容，私有化部署，适合医疗文件存储                          |
| **AI/LLM**   | OpenAI API 兼容接口             | -           | 支持 GPT-4o / 国产大模型，统一接口适配                         |

| **容器化**   | Docker + Docker Compose         | -           | 开发环境一致性，便于私有化部署                                 |
| **反向代理** | Nginx                           | 1.24+       | 静态资源服务、HTTPS 终端、负载均衡                             |
| **CI/CD**    | GitHub Actions                  | -           | 自动化测试、构建、部署                                         |

## 2. 系统架构设计

### 2.1 分层架构

```
┌─────────────────────────────────────────────┐
│              Presentation Layer              │
│         (React SPA + Ant Design)            │
├─────────────────────────────────────────────┤
│              API Gateway Layer               │
│           (Nginx + Rate Limiting)           │
├─────────────────────────────────────────────┤
│             Application Layer                │
│  ┌──────────────────────────────────────┐   │
│  │         FastAPI Routers              │   │
│  │  /auth  /projects  /subjects  /ai    │   │
│  └──────────────┬───────────────────────┘   │
│  ┌──────────────▼───────────────────────┐   │
│  │         Service Layer                │   │
│  │  业务逻辑编排、权限校验、数据校验     │   │
│  └──────────────┬───────────────────────┘   │
│  ┌──────────────▼───────────────────────┐   │
│  │         Repository Layer             │   │
│  │  数据访问、ORM 操作、缓存策略         │   │
│  └──────────────────────────────────────┘   │
├─────────────────────────────────────────────┤
│             Infrastructure Layer            │
│  PostgreSQL │ Redis │ MinIO │ Celery Workers│
└─────────────────────────────────────────────┘
```

### 2.2 核心模块划分

| 模块             | 职责                                                         | 依赖                |
| ---------------- | ------------------------------------------------------------ | ------------------- |
| `auth`           | 用户认证、JWT 令牌管理、权限校验                             | PostgreSQL, Redis   |
| `project`        | 项目 CRUD、项目配置管理                                      | PostgreSQL          |
| `criteria`       | 入排标准 CRUD、标准排序与启用管理                            | PostgreSQL          |
| `subject`        | 受试者 CRUD、受试者状态管理                                  | PostgreSQL          |
| `file`           | 文件上传/下载/删除、文件解析调度                             | MinIO, PostgreSQL   |
| `document_parser`| PDF/图片文本提取、分片、实体抽取                             | PyMuPDF, PaddleOCR  |
| `ai_engine`      | AI 匹配分析、提示词构建、结果解析、置信度计算                | LLM API, Celery     |
| `screening`      | 初筛任务调度、结果汇总、总体结论生成                         | Celery, PostgreSQL  |
| `evaluation`     | 匹配结果查询、人工复核、改判                                 | PostgreSQL          |
| `audit`          | 审计日志记录与查询                                           | PostgreSQL          |

## 3. 数据库设计

### 3.1 ER 关系图

```
users
  │
  ├── created_by ──► projects
  │                    │
  │                    ├── 1:N ──► eligibility_criteria
  │                    │
  │                    ├── 1:N ──► subjects
  │                    │              │
  │                    │              ├── 1:N ──► uploaded_files
  │                    │              │              │
  │                    │              │              └── 1:N ──► document_chunks
  │                    │              │
  │                    │              ├── 1:N ──► screening_runs
  │                    │              │              │
  │                    │              │              └── 1:N ──► criterion_evaluations
  │                    │              │                             │
  │                    │              │                             └── 1:N ──► evaluation_citations
  │                    │              │
  │                    └── 1:N ──► uploaded_files (file_scope=project_protocol)
  │
  └── user_id ──► audit_logs
```

### 3.2 DDL 定义

```sql
-- ============================================
-- 用户表
-- ============================================
CREATE TABLE users (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    username        VARCHAR(64)  NOT NULL UNIQUE,
    password_hash   VARCHAR(256) NOT NULL,
    display_name    VARCHAR(128) NOT NULL,
    role            VARCHAR(32)  NOT NULL DEFAULT 'crc'
                        CHECK (role IN ('admin','project_manager','crc','viewer')),
    email           VARCHAR(256),
    status          VARCHAR(16)  NOT NULL DEFAULT 'active'
                        CHECK (status IN ('active','disabled')),
    created_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ  NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_users_username ON users(username);

-- ============================================
-- 项目表
-- ============================================
CREATE TABLE projects (
    id                     UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_no             VARCHAR(64)  NOT NULL UNIQUE,
    study_name             VARCHAR(512) NOT NULL,
    study_short_name       VARCHAR(256),
    indication             VARCHAR(256),
    phase                  VARCHAR(64),
    sponsor                VARCHAR(256),
    principal_investigator VARCHAR(256),
    project_manager        VARCHAR(256),
    status                 VARCHAR(32) NOT NULL DEFAULT 'draft'
                               CHECK (status IN ('draft','configuring','screening','paused','completed')),
    description            TEXT,
    ai_prompt              TEXT,
    created_by             UUID NOT NULL REFERENCES users(id),
    created_at             TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at             TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_projects_status ON projects(status);
CREATE INDEX idx_projects_indication ON projects(indication);

-- ============================================
-- 入排标准表
-- ============================================
CREATE TABLE eligibility_criteria (
    id                    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id            UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    criterion_code        VARCHAR(16) NOT NULL,
    criterion_type        VARCHAR(16) NOT NULL
                              CHECK (criterion_type IN ('inclusion','exclusion')),
    criterion_text        TEXT NOT NULL,
    criterion_explanation TEXT,
    ai_instruction        TEXT,
    required_fields       JSONB DEFAULT '[]',
    sort_order            INT DEFAULT 0,
    is_active             BOOLEAN DEFAULT TRUE,
    created_at            TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at            TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    UNIQUE(project_id, criterion_code)
);

CREATE INDEX idx_criteria_project ON eligibility_criteria(project_id);
CREATE INDEX idx_criteria_type ON eligibility_criteria(criterion_type);

-- ============================================
-- 受试者表
-- ============================================
CREATE TABLE subjects (
    id               UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id       UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    subject_no       VARCHAR(64) NOT NULL,
    site_no        VARCHAR(256),
    gender           VARCHAR(8) CHECK (gender IN ('男','女')),
    age              INT,
    birth_year       INT,
    diagnosis        VARCHAR(512),
    material_count   INT DEFAULT 0,
    screening_status VARCHAR(32) NOT NULL DEFAULT 'not_started'
                         CHECK (screening_status IN (
                             'not_started','parsing','matching','need_review','completed','failed'
                         )),
    overall_result   VARCHAR(32)
                         CHECK (overall_result IS NULL OR overall_result IN (
                             'recommended','excluded','insufficient_data','manual_review'
                         )),
    created_by       UUID REFERENCES users(id),
    created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    UNIQUE(project_id, subject_no)
);

CREATE INDEX idx_subjects_project ON subjects(project_id);
CREATE INDEX idx_subjects_status ON subjects(screening_status);

-- ============================================
-- 上传文件表
-- ============================================
CREATE TABLE uploaded_files (
    id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id   UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    subject_id   UUID REFERENCES subjects(id) ON DELETE SET NULL,
    file_name    VARCHAR(512) NOT NULL,
    file_path    VARCHAR(1024) NOT NULL,
    file_type    VARCHAR(32) NOT NULL
                     CHECK (file_type IN (
                         'protocol','medical_record','lab_report','exam_report',
                         'imaging_report','pathology_report','discharge_summary',
                         'informed_consent','other'
                     )),
    file_scope   VARCHAR(32) NOT NULL
                     CHECK (file_scope IN ('subject_data','project_protocol')),
    mime_type    VARCHAR(128),
    file_size    BIGINT,
    page_count   INT,
    parse_status VARCHAR(16) NOT NULL DEFAULT 'pending'
                     CHECK (parse_status IN ('pending','parsing','parsed','failed')),
    uploaded_by  UUID REFERENCES users(id),
    uploaded_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_files_project ON uploaded_files(project_id);
CREATE INDEX idx_files_subject ON uploaded_files(subject_id);
CREATE INDEX idx_files_scope ON uploaded_files(file_scope);

-- ============================================
-- 文件解析片段表
-- ============================================
CREATE TABLE document_chunks (
    id                 UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    file_id            UUID NOT NULL REFERENCES uploaded_files(id) ON DELETE CASCADE,
    project_id         UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    subject_id         UUID REFERENCES subjects(id) ON DELETE SET NULL,
    page_no            INT NOT NULL,
    chunk_index        INT NOT NULL,
    content            TEXT NOT NULL,
    bbox               JSONB,
    extracted_entities JSONB DEFAULT '{}',
    created_at         TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_chunks_file ON document_chunks(file_id);
CREATE INDEX idx_chunks_subject ON document_chunks(subject_id);
CREATE INDEX idx_chunks_page ON document_chunks(file_id, page_no);

-- ============================================
-- AI 分析任务表
-- ============================================
CREATE TABLE screening_runs (
    id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id     UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    subject_id     UUID NOT NULL REFERENCES subjects(id) ON DELETE CASCADE,
    run_no         VARCHAR(32) NOT NULL,
    status         VARCHAR(16) NOT NULL DEFAULT 'queued'
                       CHECK (status IN ('queued','running','completed','failed')),
    model_name     VARCHAR(64),
    prompt_version VARCHAR(32),
    started_at     TIMESTAMPTZ,
    completed_at   TIMESTAMPTZ,
    error_message  TEXT,
    created_by     UUID REFERENCES users(id)
);

CREATE INDEX idx_runs_subject ON screening_runs(subject_id);
CREATE INDEX idx_runs_status ON screening_runs(status);

-- ============================================
-- 受试者-标准匹配结果表
-- ============================================
CREATE TABLE criterion_evaluations (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    run_id          UUID NOT NULL REFERENCES screening_runs(id) ON DELETE CASCADE,
    project_id      UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    subject_id      UUID NOT NULL REFERENCES subjects(id) ON DELETE CASCADE,
    criterion_id    UUID NOT NULL REFERENCES eligibility_criteria(id),
    criterion_code  VARCHAR(16) NOT NULL,
    criterion_type  VARCHAR(16) NOT NULL,
    criterion_text  TEXT NOT NULL,
    ai_result       VARCHAR(32) NOT NULL,
    confidence_score INT CHECK (confidence_score BETWEEN 0 AND 100),
    ai_rationale    TEXT,
    manual_result   VARCHAR(32),
    manual_comment  TEXT,
    reviewer_id     UUID REFERENCES users(id),
    reviewed_at     TIMESTAMPTZ,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_evals_run ON criterion_evaluations(run_id);
CREATE INDEX idx_evals_subject ON criterion_evaluations(subject_id);
CREATE INDEX idx_evals_criterion ON criterion_evaluations(criterion_id);

-- ============================================
-- 判断依据引用表
-- ============================================
CREATE TABLE evaluation_citations (
    id                    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    evaluation_id         UUID NOT NULL REFERENCES criterion_evaluations(id) ON DELETE CASCADE,
    file_id               UUID REFERENCES uploaded_files(id) ON DELETE SET NULL,
    file_name             VARCHAR(512),
    file_type             VARCHAR(32),
    page_no               INT,
    chunk_id              UUID REFERENCES document_chunks(id) ON DELETE SET NULL,
    quoted_text           TEXT,
    extracted_fact        TEXT,
    relevance_explanation TEXT,
    created_at            TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_citations_eval ON evaluation_citations(evaluation_id);
CREATE INDEX idx_citations_file ON evaluation_citations(file_id);

-- ============================================
-- 审计日志表
-- ============================================
CREATE TABLE audit_logs (
    id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    project_id   UUID REFERENCES projects(id) ON DELETE SET NULL,
    subject_id   UUID REFERENCES subjects(id) ON DELETE SET NULL,
    user_id      UUID NOT NULL REFERENCES users(id),
    action_type  VARCHAR(64) NOT NULL,
    target_type  VARCHAR(64),
    target_id    UUID,
    before_value JSONB,
    after_value  JSONB,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_audit_project ON audit_logs(project_id);
CREATE INDEX idx_audit_user ON audit_logs(user_id);
```

## 5. AI 引擎设计

### 5.1 整体流程

```
受试者素材
    │
    ▼
┌──────────────┐
│ 1. 文件解析   │  PyMuPDF + PaddleOCR
│    文本提取   │  → document_chunks
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 2. 实体抽取   │  LLM 结构化输出
│    关键信息   │  → extracted_entities
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 3. 提示词构建  │  项目 ai_prompt + 标准 ai_instruction
│              │  + 受试者 chunks + 标准文本
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 4. LLM 逐条   │  每条标准独立调用
│    匹配判断   │  → ai_result + confidence + rationale + citations
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 5. 结果汇总   │  综合评分 + 总体结论 + AI 建议
│    生成报告   │  → overall_result + overall_score
└──────────────┘
```

### 5.2 文件解析策略

| 文件类型     | 解析方式                          | 分片策略                           |
| ------------ | --------------------------------- | ---------------------------------- |
| PDF（文字版）| PyMuPDF 直接提取文本              | 按页分片，每页一个 chunk           |
| PDF（扫描件）| PyMuPDF 提取页面图片 → PaddleOCR  | 按页分片                           |
| JPG/PNG      | PaddleOCR 直接识别                | 整张图片一个 chunk                 |
| DOC/DOCX     | python-docx 提取文本              | 按段落分片，每段不超过 1000 字符   |

**实体抽取 Prompt 示例：**

```
请从以下临床文档片段中抽取结构化实体信息，以 JSON 格式返回：
{
  "age": 年龄数值或null,
  "birth_date": 出生日期或null,
  "gender": "男/女"或null,
  "diagnosis": "诊断结果"或null,
  "pathology": "病理诊断"或null,
  "ecog_score": ECOG评分或null,
  "lab_results": [{"name": "指标名", "value": "数值", "unit": "单位"}],
  "treatments": ["治疗记录"],
  "infections": ["感染记录"],
  "autoimmune_diseases": ["自身免疫疾病"]
}

文档内容：
{chunk_content}
```

### 5.3 匹配判断 Prompt 设计

每条标准独立构建一次 LLM 调用，Prompt 结构如下：

```
## 系统角色
你是一个临床研究受试者筛选专家。请严格按照给定的标准进行判断。

## 项目信息
- 项目名称：{study_name}
- 适应症：{indication}

## 项目级判断原则
{project.ai_prompt}

## 当前标准
- 编号：{criterion.criterion_code}
- 类型：{criterion.criterion_type}（inclusion=入选标准 / exclusion=排除标准）
- 标准内容：{criterion.criterion_text}
- 标准解释：{criterion.criterion_explanation}
- 判断要点：{criterion.ai_instruction}

## 受试者信息
- 编号：{subject.subject_no}
- 年龄：{subject.age}
- 性别：{subject.gender}
- 诊断：{subject.diagnosis}

## 受试者资料（已解析）
{document_chunks_content}
（每条 chunk 标注文件名、页码）

## 输出要求
请以 JSON 格式返回判断结果：
{
  "result": "pass|fail|exclusion_hit|exclusion_not_hit|insufficient_data|manual_review",
  "confidence": 0-100,
  "rationale": "判断依据的完整说明",
  "citations": [
    {
      "file_name": "文件名",
      "file_type": "文件类型",
      "page_no": 页码,
      "chunk_index": 片段序号,
      "quoted_text": "引用的原文片段",
      "extracted_fact": "从原文抽取的事实",
      "relevance_explanation": "该证据为何支持当前判断"
    }
  ],
  "missing_info": "如果资料不足，说明缺少什么信息"
}

## 重要约束
1. 不得凭空推断，所有判断必须基于上传资料中的实际内容
2. 每条引用必须精确到文件名和页码
3. 如果资料中找不到明确证据，必须标记为 insufficient_data 或 manual_review
4. 置信度评分规则：有直接证据且明确 ≥ 85；有间接证据 60-84；资料不足 < 60
```

### 5.4 总体结论生成逻辑

AI 完成所有标准判断后，由系统（非 LLM）按规则生成总体结论：

```python
def compute_overall_result(evaluations):
    inclusion_pass = sum(1 for e in evaluations
                         if e.criterion_type == 'inclusion' and e.ai_result == 'pass')
    inclusion_fail = sum(1 for e in evaluations
                         if e.criterion_type == 'inclusion' and e.ai_result == 'fail')
    inclusion_insufficient = sum(1 for e in evaluations
                                 if e.criterion_type == 'inclusion'
                                 and e.ai_result in ('insufficient_data', 'manual_review'))

    exclusion_hit = sum(1 for e in evaluations
                        if e.criterion_type == 'exclusion' and e.ai_result == 'exclusion_hit')
    exclusion_insufficient = sum(1 for e in evaluations
                                  if e.criterion_type == 'exclusion'
                                  and e.ai_result in ('insufficient_data', 'manual_review'))

    has_pending_review = any(e.ai_result == 'manual_review' for e in evaluations)

    # 规则引擎
    if exclusion_hit > 0:
        return 'excluded'
    if inclusion_fail > 0 or inclusion_insufficient > 0 or exclusion_insufficient > 0:
        if has_pending_review:
            return 'manual_review'
        return 'insufficient_data'
    if has_pending_review:
        return 'manual_review'
    return 'recommended'
```

**综合评分计算：**

```python
def compute_overall_score(evaluations):
    if not evaluations:
        return 0
    total_weight = 0
    weighted_sum = 0
    for e in evaluations:
        weight = 1.0
        # 排除标准命中则大幅扣分
        if e.criterion_type == 'exclusion' and e.ai_result == 'exclusion_hit':
            weighted_sum += 0
            total_weight += weight * 2  # 排除标准权重加倍
            continue
        # 入选标准不通过扣分
        if e.criterion_type == 'inclusion' and e.ai_result == 'fail':
            weighted_sum += 0
            total_weight += weight
            continue
        # 资料不足按置信度的 50% 计算
        if e.ai_result in ('insufficient_data', 'manual_review'):
            weighted_sum += e.confidence_score * 0.5
            total_weight += weight
            continue
        # 正常按置信度加权
        weighted_sum += e.confidence_score
        total_weight += weight

    return round(weighted_sum / total_weight) if total_weight > 0 else 0
```

### 13.2 健康检查

```python
@app.get("/health")
async def health_check():
    """基础健康检查"""
    return {"status": "ok"}

@app.get("/health/detailed")
async def detailed_health_check():
    """详细健康检查"""
    checks = {
        "database": await check_db(),
        "redis": await check_redis(),
        "minio": await check_minio(),
        "llm": await check_llm_api(),
        "celery": await check_celery_workers(),
    }
    all_healthy = all(v["status"] == "ok" for v in checks.values())
    return {
        "status": "ok" if all_healthy else "degraded",
        "checks": checks,
    }
```
